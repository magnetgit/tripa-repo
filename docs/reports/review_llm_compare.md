# 리뷰 키워드 요약: GPT vs 로컬 모델

`python manage.py compare_review_llm` 결과 (DB 저장 안 함). 장소 5곳 × 2번, 프롬프트는 `review_service.PROMPT` 그대로.

## 모델별

| 모델 | JSON 정상 | 규칙 지킴 | 키워드 근거 | 키워드 수 | 요약 길이 | 평균 시간 |
|---|---|---|---|---|---|---|
| `gpt-4o-mini` | 10/10 | 9/10 | 94% | 5.0개 | 30자 | 1.5초 |
| `qwen3:8b` | 10/10 | 10/10 | 100% | 3.6개 | 29자 | 1.5초 |
| `exaone3.5:7.8b` | 10/10 | 9/10 | 100% | 3.9개 | 43자 | 1.2초 |
| `llama3.1:8b` | 10/10 | 10/10 | 85% | 2.3개 | 24자 | 1.0초 |

- 규칙: 키워드 1~5개·2~8글자·명사구(…요/…다/…고/…도로 끝나지 않음), 요약 60자 이내, 영어 섞이지 않음
- 키워드 근거: 키워드 낱말이 리뷰 글에 실제로 나오는 비율 (지어냈는지 대략)

## 정리 (11/10, RTX 3060 8GB · Ollama 0.40, 시연 PC 같은 사양)

- **네 모델 모두 JSON은 한 번도 안 깨짐 (40/40).** 로컬 모델로 바꿔도 리뷰 요약 기능이 멈출 걱정은 없어요
- **속도:** 로컬 모델(1.0~1.5초)이 GPT(1.5초)와 비슷하거나 조금 빨라요 (모델을 GPU에 올린 뒤 기준)
- **gpt-4o-mini:** 키워드를 항상 5개 채움. 리뷰 문구를 그대로 가져오는 버릇이 조금 남음(`줄 서도` 1번)
- **qwen3:8b (설정 B 기본):** 규칙을 다 지킴. 키워드 3~4개, 단점(주차·가격)은 잘 안 적음
- **exaone3.5:7.8b (예비):** 요약이 가장 길고(평균 43자) 단점까지 적음. 리뷰에 실제로 있는 내용
- **llama3.1:8b:** 키워드가 가장 적고(2.3개) 요약이 짧음
- **설정 B 그대로 써도 돼요:** 리뷰 요약은 `qwen3:8b`로 충분하고, 내용이 더 풍부한 쪽은 `exaone3.5:7.8b`
- **한계:** 리뷰가 `seed_demo` 데모 리뷰(문구 조합)라 장소끼리 표현이 비슷해요. 실제 리뷰가 쌓이면 다시 돌려 볼 만해요

### PROMPT 보완 전후 (11/10)
- 보완: PROMPT에 "리뷰 문장을 그대로 쓰지 말 것 (예: '양이 많고' → '푸짐한 양')" + 저장 전에 `…요/…다/…고/…도`로 끝나는 키워드를 코드로 거름 + 요약 60자로 자르기(PROMPT와 맞춤)
- 문장형 키워드 (모델 답 그대로 기준, 코드 거르기 전): GPT 1번 → 1번 (그대로, 코드가 저장 전에 거름), EXAONE 2번 → 0번 (남은 `파도`는 명사인데 끝 글자 때문에 검사에 걸린 것)
- 실제 `summarize_review`(GPT) 4곳: `푸짐한 양`·`줄 서는 대기`·`가족과 방문`처럼 명사로 나옴, 요약 30~34자
