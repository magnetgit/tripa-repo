# 리뷰 키워드 요약: GPT vs 로컬 모델

`python manage.py compare_review_llm` 결과 (DB 저장 안 함). 장소 5곳 × 2번, 프롬프트는 `review_service.PROMPT` 그대로.

## 모델별

| 모델 | JSON 정상 | 규칙 지킴 | 키워드 근거 | 키워드 수 | 요약 길이 | 평균 시간 |
|---|---|---|---|---|---|---|
| `gpt-4o-mini` | 10/10 | 9/10 | 96% | 5.0개 | 31자 | 1.6초 |
| `qwen3:8b` | 10/10 | 10/10 | 95% | 3.0개 | 28자 | 1.4초 |
| `exaone3.5:7.8b` | 10/10 | 8/10 | 100% | 3.9개 | 40자 | 1.2초 |
| `llama3.1:8b` | 10/10 | 10/10 | 100% | 2.7개 | 30자 | 1.1초 |

- 규칙: 키워드 1~5개·2~8글자·명사구(…요/…다/…고/…도로 끝나지 않음), 요약 60자 이내, 영어 섞이지 않음
- 키워드 근거: 키워드 낱말이 리뷰 글에 실제로 나오는 비율 (지어냈는지 대략)

## 정리 (11/10, RTX 3060 8GB · Ollama 0.40, 시연 PC 같은 사양)

- **네 모델 모두 JSON은 한 번도 안 깨짐 (40/40).** 로컬 모델로 바꿔도 리뷰 요약 기능이 멈출 걱정은 없어요
- **속도:** 로컬 모델(1.1~1.4초)이 GPT(1.6초)보다 조금 빨라요 (모델을 GPU에 올린 뒤 기준, 처음 한 번은 몇 초 더)
- **gpt-4o-mini:** 키워드를 항상 5개 꽉 채움. 대신 리뷰 문구를 그대로 가져와서 `양이 많고`·`줄 서도`처럼 명사구가 아닌 키워드가 나와요
- **qwen3:8b (설정 B 기본):** 규칙은 다 지키지만 키워드가 3개로 적고, 요약에 단점(주차·가격)을 거의 안 적어요
- **exaone3.5:7.8b (예비):** 요약이 가장 길고(평균 40자) 단점까지 같이 적어요. 리뷰에 실제로 있는 내용이에요(`비싸`가 해동용궁사 1개·오륙도 3개 리뷰에 있음). 가끔 `양이 많고` 같은 문장형 키워드
- **llama3.1:8b:** 키워드가 가장 적고(2.7개) 요약이 리뷰 한 줄을 그대로 옮긴 것처럼 짧을 때가 있어요
- **설정 B 그대로 써도 돼요:** 리뷰 요약은 `qwen3:8b`로 충분하고, 내용이 더 풍부한 쪽은 `exaone3.5:7.8b`
- **한계:** 리뷰가 `seed_demo` 데모 리뷰(문구 조합)라 장소끼리 표현이 비슷해요. 형식·속도·지키는 규칙 비교로는 충분하지만, 실제 사용자 리뷰가 쌓이면 다시 돌려 볼 만해요

### 보완할 점 (🟧 `review_service`)
- 문장형 키워드(`…요`·`…고`·`…도`로 끝남)가 GPT·EXAONE에서 나와요 → PROMPT에 "리뷰 문장을 그대로 쓰지 말 것" 한 줄 + 저장 전에 걸러내기
- PROMPT는 요약 60자인데 코드는 100자에서 잘라요 (`review_service.py:60`) → 숫자 맞추기
