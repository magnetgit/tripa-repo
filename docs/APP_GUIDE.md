# 앱으로 확장하기 (APP_GUIDE)

TRIPA를 폰·태블릿 웹에서 **앱**까지 넓힐 때의 순서와 파트별 할 일입니다.
코드는 각 파트가 직접 작성합니다. 이 문서는 개념과 순서만 적습니다.

## 추천 순서: 반응형 웹 → PWA → (필요하면) 스토어 앱
| 단계 | 무엇 | 사용자가 느끼는 것 | 난이도 |
|---|---|---|---|
| 1. 반응형 웹 | 같은 Django 화면이 폰·태블릿 크기에 맞게 바뀜 | 브라우저에서 폰으로 써도 편함 | 낮음 |
| 2. PWA | 웹에 '앱 정보 파일'과 '오프라인 캐시'를 더함 | 홈 화면에 아이콘으로 설치, 전체 화면, 적용한 일정 오프라인 보기 | 중간 |
| 3. 스토어 앱 | PWA를 감싸는 앱 껍데기(예: Capacitor)로 Play 스토어·앱 스토어에 올림 | 스토어에서 설치, 푸시 알림 | 높음 |

- **이번 프로젝트 기간에는 2단계(PWA)까지를 권장**합니다. 같은 코드 하나로 PC·폰·태블릿·'설치형 앱'을 모두 보여줄 수 있습니다.
- 3단계는 비용과 심사가 있습니다: Google Play 개발자 등록 1회 25달러, Apple 개발자 프로그램 연 99달러 + Mac 필요. Apple은 웹을 그대로 감싸기만 한 앱을 반려할 수 있어서(가이드라인 4.2) 푸시 알림·오프라인 같은 앱 기능이 있어야 합니다.

## 1단계: 반응형 웹 (🟦 중심)
- 기준 폭: 폰 360px 전후 / 태블릿 768px 전후 / PC 1080px 이상 (목업 '모바일 화면' 탭)
- 폰: 아래 탭바 5개(대화·일정·지도·게시판·내 정보), 태블릿: 왼쪽 아이콘 메뉴 + 2단, PC: 옛 왼쪽 메뉴
- 🟧 백엔드: 화면별로 다른 HTML을 만들지 않습니다. 같은 뷰·같은 JSON을 쓰고 배치만 CSS로 바꿉니다.

## 2단계: PWA
| 할 일 | 담당 | 설명 |
|---|---|---|
| 앱 정보 파일(web app manifest) | 🟦 | 앱 이름, 아이콘(192·512px, 산 로고), 시작 주소, 테마 색 `#2d6cdf` |
| 서비스 워커(오프라인 캐시) | 🟦 | CSS·JS·아이콘과 '적용한 일정' 화면을 캐시. 채팅·결제성 요청은 캐시하지 않음 |
| 위 두 파일을 올바른 주소·형식으로 내보내기 | 🟧 | manifest는 JSON 형식으로, 서비스 워커는 사이트 최상위 범위에서 열리도록 Django `urls`·static 설정 |
| **HTTPS 배포** | 🟧 | PWA 설치와 서비스 워커는 HTTPS에서만 동작 (EC2 + nginx + 인증서) |
| 오프라인용 일정 데이터 | 🟧 | 적용한 일정을 한 번에 받는 JSON API (일정·장소·시간·금액) |
| 알림 문구 키 | 🟩 | 날씨 변경 제안, 여행 후 리뷰 요청. 문장은 화면이 언어별로 만들고 AI는 키를 보냄 |

## 3단계: 스토어 앱 (선택)
| 할 일 | 담당 | 설명 |
|---|---|---|
| 앱 껍데기 프로젝트 | 🟦 | Capacitor 등으로 배포 주소(또는 빌드한 정적 파일)를 감쌈 |
| 로그인 방식 점검 | 🟧 | 지금은 Django 세션 쿠키. 앱이 다른 주소에서 API를 부르면 CSRF·CORS 설정이나 토큰 방식이 필요 |
| 푸시 알림 | 🟧 | 기기 토큰 저장 테이블, Firebase Cloud Messaging(FCM) 발송 |
| 푸시 보낼 때 | 🟩 | 언제 보낼지 규칙(출발 전날 비 예보, 귀가 다음 날 리뷰 요청) |
| 스토어 등록 | 팀 | 개인정보 처리방침 주소, 스크린샷, 심사 대응 |

## 지도(카카오맵) 주의점
지금 코드: 화면 지도는 **카카오맵 JavaScript SDK**(`static/sherpaapp/js/travel_chat.js`, 키 `KAKAO_MAP_API_KEY`), 장소 검색·경로는 서버가 **REST API**(`place_service.py`, `route_service.py`)로 부릅니다.

| 화면 | 쓰는 지도 | 조건·주의 |
|---|---|---|
| PC·폰·태블릿 브라우저 | JavaScript SDK (지금 코드 그대로) | 카카오 개발자 콘솔 **[플랫폼 키] > [JavaScript 키] > JavaScript SDK 도메인**에 배포 주소(`https://…`)와 개발 주소(`http://localhost:8000`, `http://127.0.0.1:8000`)를 **스킴·포트까지 정확히** 등록. 안 하면 401 domain mismatched |
| PWA (홈 화면 설치) | JavaScript SDK | 웹과 같은 주소라 추가 작업 없음. **지도 타일은 인터넷이 있어야** 보임 → 오프라인에서는 일정 목록(아래 시트)만 보여주기 |
| 스토어 앱 (Capacitor 등) | 띄우는 방식에 따라 다름 | 아래 3가지 중 선택 |

스토어 앱에서 지도를 띄우는 3가지 방법
1. **앱이 배포 주소를 그대로 띄움** (권장): 웹뷰 주소가 배포 도메인이라 JS SDK가 그대로 동작. 대신 오프라인에서는 화면이 안 열림
2. **앱 안에 화면 파일을 넣어 띄움**: 웹뷰 주소가 iOS `capacitor://localhost`, Android `https://localhost`(설정에 따라 다름)가 됨. 카카오 도메인 등록은 `http://`·`https://`만 받아서 **iOS는 등록이 막힌 사례가 있음**. 실제 웹뷰 주소를 확인하고 등록 가능 여부부터 점검
3. **지도 화면만 네이티브 SDK(Android/iOS)**: 가장 확실하지만 지도 화면을 따로 만들어야 함. 콘솔에 Android 패키지명·키 해시, iOS 번들 ID 등록, **네이티브 앱 키** 사용
   - 네이티브 SDK를 써도 **PC·브라우저는 JavaScript SDK 그대로**입니다(네이티브 SDK는 Android/iOS 전용). 한 카카오 앱 안에 JavaScript 키·네이티브 앱 키·REST API 키가 같이 있습니다.

파트별
- 🟦 지도 화면 하나에서 날짜 전환 → 핀·동선·아래 목록이 같이 바뀌게 (목업 '모바일 화면' ④). 오프라인이면 목록만
- 🟧 웹 지도와 앱 지도가 **같은 JSON**(장소 이름, 위도·경도, 순서, 날짜)을 받게 응답을 하나로 유지. 배포 도메인이 정해지면 카카오 콘솔 등록
- 🟩 영향 없음 (추천 결과의 위도·경도 키만 `mock.json`과 맞추기)

## 파트별 체크 (앱을 시작할 때)
- 🟦 화면이 쓰는 데이터를 모두 `fetch`로 받는지(템플릿에 박힌 값이 있으면 앱 오프라인에서 안 보임)
- 🟧 모든 API가 JSON으로 같은 키를 주는지(`mock.json` 기준), 로그인 만료 시 401을 주는지
- 🟩 AI 응답이 문장 대신 키를 주는 규칙을 지키는지(앱·웹 언어가 달라도 같은 응답)
